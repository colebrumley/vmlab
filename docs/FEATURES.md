## Reasons

- `exec_agent` on `vz-macos`: no host-side agent channel for VZ guests in v1; use exec_ssh.
- `exec_agent` on `vz-linux`: no host-side agent channel for VZ guests in v1; use exec_ssh.
- `gui_preboot` on `vz-macos`: the VZ display is reached through an in-guest VNC server, which needs a running OS.
- `gui_preboot` on `vz-linux`: the VZ display is reached through an in-guest VNC server, which needs a running OS.
- `gui_accel` on `qemu-hvf`: QEMU guests get no GPU on this host in v1.
- `gui_accel` on `qemu-tcg`: QEMU guests get no GPU on this host in v1.
- `serial` on `vz-macos`: macOS guests have no serial console under VZ.
- `gdb` on `vz-macos`: Virtualization.framework exposes no public GDB stub.
- `gdb` on `vz-linux`: Virtualization.framework exposes no public GDB stub.
- `introspection` on `vz-macos`: Virtualization.framework has no public API for it.
- `introspection` on `vz-linux`: Virtualization.framework has no public API for it.
- `memory_dump` on `vz-macos`: Virtualization.framework has no public API for it.
- `memory_dump` on `vz-linux`: Virtualization.framework has no public API for it.
- `direct_kernel_boot` on `vz-macos`: macOS guests boot only from their own disk.
- `custom_firmware` on `vz-macos`: Virtualization.framework boots only Apple EFI or a Linux kernel.
- `custom_firmware` on `vz-linux`: Virtualization.framework boots only Apple EFI or a Linux kernel.
- `custom_devices` on `vz-macos`: Virtualization.framework boots only Apple EFI or a Linux kernel.
- `custom_devices` on `vz-linux`: Virtualization.framework boots only Apple EFI or a Linux kernel.
- `halt_at_start` on `vz-macos`: Virtualization.framework exposes no public GDB stub.
- `halt_at_start` on `vz-linux`: Virtualization.framework exposes no public GDB stub.
- `rosetta` on `vz-macos`: Rosetta for Linux is offered only to Linux guests under VZ.
- `rosetta` on `qemu-hvf`: Rosetta for Linux is offered only to Linux guests under VZ.
- `rosetta` on `qemu-tcg`: Rosetta for Linux is offered only to Linux guests under VZ.
- `nested_virt` on `vz-macos`: VZ offers nested virtualization only to Linux guests.
- `nested_virt` on `qemu-hvf`: HVF does not expose nested virtualization to QEMU guests.
- `cloud_init` on `vz-macos`: cloud-init is for Linux guests.
- `many_guests` on `vz-macos`: macOS allows at most two macOS guests at once.
