## `host_facts`

Report what this Mac can run: macOS version, chip, memory and free memory, free disk, whether QEMU, Tart and Rosetta are installed, whether the VZ runner is signed, how many guests (and macOS guests) run now, the image cache size, and the slow-probe results. Cheap and side-effect free; call it first in a session, or when vm_plan's answer surprises you. Returns HostFacts.

**Input**

None.

**Result**

```
{ osVersion, chip: { model, generation? }, memoryGB, freeMemoryGB, freeDiskGB, isRoot,
  qemu: { present, version?, path?, accelerators }, tart: { present, version? },
  rosettaInstalled, nestedSupported, runnerSigned, runningMacOSGuests, runningGuests,
  imagesBytes,
  probes: { schemaVersion,
            probes: { <probe>: { result, probedAt?, osVersion?, qemuVersion? } } } }
```

## `host_doctor`

Check the host's prerequisites (QEMU, Tart, Rosetta, the signed VZ runner and its entitlement, free memory and disk, running guest counts) and report each as ok, missing or unknown with the command that fixes it, plus the persisted slow-probe results with their dates. Use it when a tool reports host_missing_tool or unverified_capability. probe: true also runs the slow probes, each booting a throwaway guest (minutes), and records their answers so later plans can rely on them.

**Errors:** `host_missing_tool`, `limit_memory`, `timeout`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `probe` | boolean, default `false` |  | Also run the slow probes (live snapshots, GDB under HVF, vmnet); takes minutes. |

**Result**

```
{ checks: [ { check, status: ok|missing|unknown, detail?, fix? } ],
  probes: { <probe>: { result: yes|no|unknown, probedAt?, owner,
                       status?: ran|skipped|failed|not_implemented, note? } },
  runner: { path?, built, entitled }, freeMemoryGB, freeDiskGB,
  runningGuests, runningMacOSGuests }
```

## `images`

Manage the guest image cache in ~/.vmlab/images. list shows pulled and available images; pull downloads and verifies one by name (large pulls need confirm: true; a changed upstream image is not pulled over one a VM uses); remove deletes a pulled image no VM uses; register adds a local disk image (path, guest, arch, format), an IPSW (path ending .ipsw) or a kernel (kernel, initrd); template_create turns the stopped VM vm into the template name for vm_create image: name and fleets; prune removes images no VM or template uses; extract_kernel copies the kernel, initrd, System.map and config out of a pulled Linux image for direct kernel boot. vm_create pulls what it needs itself, so call this to inspect or to pre-pull.

**Errors:** `invalid_request`, `image_not_found`, `confirm_required`, `host_missing_tool`, `vm_not_found`, `wrong_state`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `action` | `list` \| `pull` \| `remove` \| `register` \| `template_create` \| `prune` \| `extract_kernel` | yes | What to do. |
| `arch` | string |  | register: the image's architecture, e.g. arm64 or x86_64. |
| `confirm` | boolean, default `false` |  | Allow a pull or prune the server asks to confirm (it states the size). |
| `format` | `raw` \| `qcow2` |  | register: disk format. |
| `guest` | `macos` \| `linux` |  | register: the image's guest OS. |
| `initrd` | string |  | register: host path of an initrd for that kernel. |
| `kernel` | string |  | register: host path of a kernel image. |
| `name` | string |  | Image name (pull, remove, register, template_create, extract_kernel). |
| `path` | string |  | register: host path (under your home or /tmp) of a raw or qcow2 disk, or an .ipsw. |
| `vm` | string |  | template_create: the stopped VM to turn into a template. |

**Result**

```
list: { images: [ { name, guest, arch, format, pulled, bytes?, template, path? } ] }
pull: { name, path, bytes, cached }
remove: { removed: [name], bytesFreed }
prune: { removed: [name], bytesFreed, kept: [name] }
register, template_create, extract_kernel: { name, path, files: [path] }
```

## `vm_plan`

Dry-run the selector: given requirements (the guest plus the features you need and prefer), say which engine profile would run the VM and what it would have, without creating anything. Use it before vm_create when unsure a combination is possible. An impossible request is not an error: the result is an Unsatisfiable object naming which profiles each feature ruled out and the smallest sets of features to drop.

**Errors:** `invalid_request`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `requirements` | [requirements](#requirements) | yes | What the VM must be. Only guest is required; every other field has a default. |
| `allowUnverified` | boolean, default `false` |  | Treat features whose slow probe has not run on this host as available, instead of failing with unverified_capability. |

**Result**

```
Plan { satisfiable: true, profile, guest, resources, features, requested, unverified,
       preferredDenied, allowUnverified, estimatedStartupSeconds, startupTier, notes }
or Unsatisfiable { satisfiable: false, code, message, hint, guest,
                   eliminated: { <feature>: [profile] }, reasons: { <feature>: { <profile>: why } },
                   suggestions: [ { drop: [feature], profile } ],
                   unverified: { <feature>: [probe] }, limit?: Error }
```

## `vm_create`

Create a VM from requirements: plans it (as vm_plan), pulls the image if needed, provisions it (SSH key, cloud-init) and by default starts it and waits for SSH. Ask in require for every channel you will use (serial, gdb, gui, checkpoint_live, ...): tools for channels the plan did not grant fail later with capability_missing. Returns the resolved plan, so read it to know what you got, plus the VM, its state and endpoints. Requested port forwards are QEMU loopback ports or, on VZ, the guest's own NAT address; forwarding says which, and endpoints.forwards[].hostReachable is where to connect. Slow (tens of seconds to minutes); sends progress.

**Errors:** `invalid_request`, `unsatisfiable`, `unverified_capability`, `limit_macos_guests`, `limit_memory`, `host_missing_tool`, `image_not_found`, `confirm_required`, `provision_failed`, `timeout`, `engine_error`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `requirements` | [requirements](#requirements) | yes | What the VM must be. Only guest is required; every other field has a default. |
| `allowUnverified` | boolean, default `false` |  | Treat features whose slow probe has not run on this host as available, instead of failing with unverified_capability. |
| `autostart` | boolean, default `true` |  | Start the VM once created. |
| `confirm` | boolean, default `false` |  | Allow a large image pull the server asks to confirm. |
| `name` | string |  | A unique name for the VM; defaults to its id. |

**Result**

```
{ plan: Plan, vm: { id, name }, state,
  endpoints: { ssh?: "host:port", ip?, serial?, display?, gdb?,
    forwards?: [ { guest, host: "127.0.0.1:port" | null, hostReachable: "addr:port" } ] },
  forwarding: { mode: hostfwd | host_reachable, note } | null }
```

## `vm_lifecycle`

Change a VM's power state. start boots it and waits for SSH; stop shuts it down gracefully (ACPI, then kill after the timeout); kill stops it at once; pause and resume freeze and thaw it in memory; reset returns the CPU to its first instruction, keeping breakpoints; destroy deletes the VM and its disk (force when another VM's disk is backed by it); clone makes a new VM name from this one's current disk or from checkpoint from. Illegal transitions fail with wrong_state listing the legal actions.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `limit_macos_guests`, `limit_memory`, `timeout`, `engine_error`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `action` | `start` \| `stop` \| `kill` \| `pause` \| `resume` \| `reset` \| `destroy` \| `clone` | yes | The transition. |
| `force` | boolean, default `false` |  | destroy: even when another VM's disk depends on this one. |
| `from` | string |  | clone: a checkpoint name to clone from (default: current disk). |
| `name` | string |  | clone: the new VM's name. |
| `timeoutSeconds` | integer, ≥ 1 |  | start: how long to wait for SSH; stop: the grace period before kill. |

**Result**

```
{ vm: { id, name }, state, durationMs }
clone: { vm: { id, name } (the new VM), state, plan }
```

## `vm_exec`

Run a shell command in the guest and return its exit code, stdout and stderr. Uses SSH, or the guest agent when the VM has no network (via). Output over 64 KB keeps the head and tail, sets truncated and saves the whole text at logPath. A command that outlives timeoutSeconds is killed and fails with timeout carrying the partial output. For long work pass background: true and poll the returned job with vm_job.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `guest_unreachable`, `timeout`, `invalid_request`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `command` | string | yes | The command, run by the guest's shell. |
| `background` | boolean, default `false` |  | Return a job id at once instead of waiting. |
| `cwd` | string |  | Working directory in the guest. |
| `env` | object |  | Extra environment variables. |
| `stdin` | string |  | Text fed to the command's standard input. |
| `timeoutSeconds` | integer, ≥ 1, default `120` |  | Kill the command after this long. |
| `user` | string |  | Run as this guest user (sudo) instead of the login user. |
| `via` | `auto` \| `ssh` \| `agent`, default `auto` |  | Transport: auto prefers SSH, else the guest agent. |

**Result**

```
{ exitCode, stdout, stderr, durationMs, truncated, logPath? }
background: { job }
```

## `vm_job`

Follow a background command started by vm_exec with background: true. read returns the output written since the last read and whether the job finished; wait blocks until it finishes or timeoutSeconds passes, then returns like read; kill stops it. Jobs survive a server restart.

**Errors:** `vm_not_found`, `invalid_request`, `guest_unreachable`, `timeout`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `job` | string | yes | The job id vm_exec returned. |
| `action` | `read` \| `wait` \| `kill` | yes | What to do with the job. |
| `timeoutSeconds` | integer, ≥ 1 |  | wait: the longest to block. |

**Result**

```
{ output, finished, exitCode? }
```

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `guest_unreachable`, `invalid_request`, `timeout`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `action` | `push` \| `pull` | yes | Direction of the copy. |
| `remote` | string | yes | Path in the guest. |
| `local` | string |  | Absolute path on the host, under your home or /tmp (push: required; pull: optional). |

**Result**

```
{ bytes, path }
```

## `vm_computer`

See and drive the guest's display like a computer-use tool. screenshot returns an image scaled so its long edge is at most maxEdge (default 1280) with the scale used; pass diffFrom a previous screenshot id to get only the changed region, or unchanged: true. zoom crops region at full resolution. Clicks, drags, mouse_move, type, key (xdotool names such as Return, ctrl+c, cmd+space), scroll and wait act, then return a fresh screenshot after settleMs. Coordinates are guest pixels unless scaled: true, which means the coordinates of the last scaled screenshot. cursor_position and screen_info return no image. Needs the gui feature.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `invalid_request`, `engine_error`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `action` | `screenshot` \| `left_click` \| `right_click` \| `middle_click` \| `double_click` \| `triple_click` \| `left_click_drag` \| `mouse_move` \| `cursor_position` \| `type` \| `key` \| `scroll` \| `wait` \| `zoom` \| `screen_info` | yes | What to do. |
| `coordinate` | array of integer, ≥ 0 (2 items) |  | [x, y]: the click, move or scroll point; the drag's end. |
| `diffFrom` | string |  | screenshot: id of an earlier screenshot of this VM; return only what changed. |
| `durationSeconds` | number, ≥ 0 |  | wait: how long to wait. |
| `format` | `png` \| `jpeg`, default `png` |  | Image encoding. |
| `maxEdge` | integer, ≥ 1, default `1280` |  | Longest edge of the returned image in pixels. |
| `quality` | integer, 1–100, default `80` |  | jpeg quality, 1 (smallest) to 100. |
| `region` | array of integer, ≥ 0 (4 items) |  | [x0, y0, x1, y1]: screenshot or zoom only this rectangle. |
| `scaled` | boolean, default `false` |  | Coordinates are in the last screenshot's scaled space, not guest pixels. |
| `scrollAmount` | integer, ≥ 1, default `3` |  | scroll: wheel clicks. |
| `scrollDirection` | `up` \| `down` \| `left` \| `right` |  | scroll: direction. |
| `settleMs` | integer, ≥ 0, default `300` |  | Delay before the screenshot that follows an action. |
| `startCoordinate` | array of integer, ≥ 0 (2 items) |  | left_click_drag: [x, y] where the drag starts. |
| `text` | string |  | type: the text to type; key: the key or chord, e.g. ctrl+alt+t. |

**Result**

```
image content block +
{ id, width, height, scale, changedRegion?: { x, y, width, height }, unchanged? }
cursor_position: { x, y }; screen_info: { width, height }
```

## `vm_serial`

The guest's serial console, captured from the first byte of boot. read returns text from byte offset since (default: the start of the buffer); tail returns the last lines lines; write sends text (include \n to press Enter); wait blocks until the regular expression pattern appears after since or timeoutSeconds passes. Every result returns the offset to pass as since next time. Use it to watch boot, kernel messages and panics, or to log in when SSH is down. Needs the serial feature.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `invalid_request`, `timeout`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `action` | `read` \| `tail` \| `write` \| `wait` | yes | What to do. |
| `lines` | integer, ≥ 1, default `50` |  | tail: how many lines. |
| `pattern` | string |  | wait: a regular expression to wait for. |
| `since` | integer, ≥ 0 |  | read, wait: the byte offset to start from. |
| `text` | string |  | write: the text to send. |
| `timeoutSeconds` | integer, ≥ 1, default `30` |  | wait: the longest to block. |

**Result**

```
{ text, offset, matched?, truncated }
```

## `vm_debug`

Debug the guest CPU through its GDB stub. info gives the endpoint a human can attach to and whether vmlab is attached; halt stops the CPU; continue resumes; step executes one instruction; wait blocks until the CPU stops (breakpoint, watchpoint) or timeoutSeconds; breakpoint_add sets one at address (kind software, hardware, or a watch_* watchpoint over size bytes); breakpoint_remove clears it; breakpoints lists them; registers reads them; read_memory returns size bytes at address as hex (with ASCII up to 256 bytes); write_memory writes hex data. Addresses are numbers in 0x hex; no symbols. Needs gdb; require halt_at_start to debug from the first instruction. The first action that needs the stub attaches, and QEMU stops the guest when a debugger attaches; continue resumes it. Breakpoints set on a running CPU leave it running.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `invalid_request`, `debug_busy`, `timeout`, `engine_error`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `action` | `info` \| `halt` \| `continue` \| `step` \| `wait` \| `breakpoint_add` \| `breakpoint_remove` \| `breakpoints` \| `registers` \| `read_memory` \| `write_memory` | yes | What to do. |
| `address` | string |  | Guest address in 0x hex, e.g. 0xffff800010000000. |
| `data` | string |  | write_memory: the bytes as hex, e.g. 1f2003d5. |
| `kind` | `software` \| `hardware` \| `watch_write` \| `watch_read` \| `watch_access`, default `software` |  | breakpoint_add, breakpoint_remove: the kind of stop point. |
| `size` | integer, ≥ 1 |  | read_memory: bytes to read; watchpoints: bytes to watch. |
| `symbolFile` | string |  | A host path to the guest's symbol file (vmlinux, a kernel .debug), recorded for the info output so a human can load it; vmlab resolves no symbols. |
| `thread` | string |  | step, continue, registers, read_memory, write_memory: the thread (CPU) to act on, as a stop reports it (e.g. p01.02). |
| `timeoutSeconds` | integer, ≥ 1, default `30` |  | wait: the longest to block. |

**Result**

```
{ stopped, reason?, pc?, registers?: { <name>: hex }, bytes?: hex, ascii?,
  breakpoints?: [ { address, kind, size? } ], endpoint, attached,
  info: connect: { gdb, lldb }, symbolFile, note }
```

| `hmp` | string |  | raw: an HMP info command, e.g. info mtree. |
| `qmp` | string |  | raw: a read-only QMP command, e.g. query-chardev. |

**Result**

```
{ query, json? | text? }
```

| `address` | string |  | Guest physical start address in 0x hex. |
| `confirm` | boolean, default `false` |  | Allow a dump the server asks to confirm (it states the size). |


## `vm_checkpoint`

Named snapshots of a VM, kept as a tree. create saves one (mode live includes memory and needs checkpoint_live; disk needs a stopped guest; auto picks live when it can, and never stops the guest for you); manifest: true also records what is installed so diff can compare. list returns the tree; restore returns the VM to name; delete removes it (recursive for one with children). diff compares from and to, each a checkpoint name, a manifest id or @now, and lists changed files, packages, services, defaults, users and login items. @latest names the newest checkpoint.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `invalid_request`, `unverified_capability`, `guest_unreachable`, `engine_error`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `action` | `create` \| `list` \| `restore` \| `delete` \| `diff` | yes | What to do. |
| `from` | string |  | diff: the older side (checkpoint, manifest id or @now). |
| `manifest` | boolean, default `false` |  | create: also take a guest manifest for diff. |
| `mode` | `auto` \| `disk` \| `live`, default `auto` |  | create: what to save. |
| `name` | string |  | create, restore, delete: the checkpoint's name; unique per VM. |
| `note` | string |  | create: a note kept with the checkpoint. |
| `recursive` | boolean, default `false` |  | delete: also delete its descendants. |
| `to` | string |  | diff: the newer side (checkpoint, manifest id or @now). |

**Result**

```
create: { checkpoint: { id, name, parent?, mode, createdAt, state, manifestPath?, note? } }
list: { current?, nodes: [ checkpoint ] }; restore: { checkpoint, state }; delete: { deleted }
diff: { from, to, path, files, packages, services, defaults, users, loginItems, profiles },
each section { added, removed, changed, truncated, entries (at most 500) }: files
{ path, change, kind, changes: { size|mode|sha256|kind|mtime: { old, new } } }, defaults
{ domain, key, change, old, new }, the others { name, change, old, new }
```

## `vm_manifest`

Take a manifest of the running guest over SSH: files under paths (size, mode, mtime, sha256) and, for profile linux, packages, enabled services, users and /etc hashes; for macos also defaults domains, Homebrew packages, launchd jobs, profiles and login items; custom covers only paths. Stored on the host; returns its id (usable as vm_checkpoint diff from or to), path and counts per section.

**Errors:** `vm_not_found`, `wrong_state`, `capability_missing`, `guest_unreachable`, `timeout`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `paths` | array of string |  | Roots to walk for files. |
| `profile` | `linux` \| `macos` \| `custom` |  | What to record besides paths; defaults to the guest's OS. |

**Result**

```
{ id, path, profile, counts: { files, packages, services, defaults, users, loginItems, profiles } }
```

## `vm_logs`

Read a VM's logs on the host: events (lifecycle, panics, warnings), serial (the console log), provision (first-boot steps), or all of them interleaved. Works for stopped VMs. Use it to find out why a VM failed to boot or provision.

**Errors:** `vm_not_found`, `invalid_request`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `vm` | string | yes | The VM's id (vm-xxxxxx) or name, as vm_list or vm_create returned it. |
| `source` | `events` \| `serial` \| `provision` \| `all`, default `all` |  | Which log. |
| `tail` | integer, ≥ 1, default `100` |  | Return only the last tail lines. |

**Result**

```
{ lines: [String] }
```

## `net_segment`

Manage private host-local Ethernet segments that guests join with a second NIC (requirements.network.segment), so guests on one Mac can reach each other by name. create makes segment name with its own 10.n.0.0/24 subnet; list shows every segment and its members; destroy removes one. Segments carry no internet; guests keep NAT for that.

**Errors:** `invalid_request`, `wrong_state`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `action` | `create` \| `list` \| `destroy` | yes | What to do. |
| `name` | string |  | create, destroy: the segment's name. |

**Result**

```
{ name, subnet, members: [ { vm, ip } ] }
list: { segments: [ { name, subnet, members } ] }
```

## `fleet`

Run several identical VMs as a group. create makes count members named <name>-1 to <name>-n from one plan of requirements (or image, a template), joins them to segment (auto makes one) and waits for SSH on each; some members may fail and are listed with their error. status reports each member; list shows fleets; exec runs command on every member, or on members, in parallel, with vm_exec's options, and returns each member's result and allSucceeded; destroy removes the fleet and its VMs.

**Errors:** `invalid_request`, `unsatisfiable`, `unverified_capability`, `limit_macos_guests`, `limit_memory`, `image_not_found`, `vm_not_found`, `timeout`, `wrong_state`

**Input**

| Field | Type | Required | Description |
|---|---|---|---|
| `action` | `create` \| `list` \| `status` \| `exec` \| `destroy` | yes | What to do. |
| `allowUnverified` | boolean, default `false` |  | Treat features whose slow probe has not run on this host as available, instead of failing with unverified_capability. |
| `command` | string |  | exec: the command, as for vm_exec. |
| `count` | integer, ≥ 1 |  | create: how many members. |
| `cwd` | string |  | exec: working directory in each guest. |
| `env` | object |  | exec: extra environment variables. |
| `image` | string |  | create: image or template; overrides requirements.image. |
| `members` | array of string |  | exec: only these members. |
| `name` | string |  | The fleet's name (every action but list). |
| `requirements` | [requirements](#requirements) |  | What the VM must be. Only guest is required; every other field has a default. |
| `segment` | string |  | create: segment to join, or auto to make one for the fleet. |
| `stdin` | string |  | exec: text fed to each member's command. |
| `timeoutSeconds` | integer, ≥ 1 |  | create: per-member wait for SSH; exec: per-member command timeout. |
| `user` | string |  | exec: run as this guest user (sudo) instead of the login user. |
| `via` | `auto` \| `ssh` \| `agent`, default `auto` |  | exec: transport, as for vm_exec. |

**Result**

```
create, status: { name, segment, subnet, members: [ { vm, id, state, ip?, natIP?,
  forwards?: [ { guest, host, hostReachable } ], error? } ] }
list: { fleets: [ { name, members } ] }
exec: { results: { <member>: ExecResult }, allSucceeded }; destroy: { destroyed: [vm] }
```
